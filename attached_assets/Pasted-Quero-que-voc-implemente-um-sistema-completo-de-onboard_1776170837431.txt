Quero que você implemente um sistema completo de onboarding, documentos, assinaturas e cadastro de usuários, integrado ao app e ao painel administrativo, com foco em organização, rastreabilidade, boa experiência mobile e controle total pelo administrador.

O sistema deve conversar com o que já foi criado antes para documentos, Integra, primeiro acesso e assinaturas, expandindo e organizando tudo de forma robusta.

1. Objetivo geral

Quero um fluxo onde:

Um usuário administrador, dentro do painel de usuários, possa cadastrar o e-mail de uma pessoa.
Essa pessoa receba ou tenha acesso a um fluxo para criar sua conta no aplicativo da Replit.
No primeiro acesso, essa pessoa passe por um passo a passo obrigatório:
criar conta / definir acesso
colocar foto de perfil
preencher dados pessoais obrigatórios
ler os documentos obrigatórios
confirmar leitura dos valores da empresa
escolher se aceita ou não o termo de uso de imagem
assinar os documentos obrigatórios, quando aplicável
Tudo isso fique registrado corretamente no painel administrativo.
Depois, a pessoa consiga rever os documentos e assinar futuramente pela aba Integra, caso não assine tudo de imediato.
O sistema tenha uma área administrativa para consultar documentos assinados e exportar em CSV.
2. Cadastro inicial do usuário pelo administrador
2.1 Painel de usuários

Quero que no painel administrativo exista uma área de Usuários onde o administrador possa:

cadastrar um novo usuário informando pelo menos:
nome
e-mail
cargo, se houver
setor, se houver
unidade, se houver
deixar esse usuário como:
convidado / pendente de ativação
ativo
inativo
gerar convite de acesso
2.2 Fluxo de convite

Quando o admin cadastrar o e-mail da pessoa:

o sistema deve permitir que esse usuário seja convidado para criar conta
esse cadastro precisa ficar ligado ao e-mail informado pelo admin
o sistema deve tratar convites pendentes
o admin deve conseguir:
reenviar convite
cancelar convite
ver status do convite
ver se a conta já foi criada ou não
2.3 Regras
não permitir duplicidade de e-mail
tratar convites expirados
permitir reativação de convite
registrar data de envio, reenvio e criação de conta
3. Criação de conta pelo usuário

Quando o usuário acessar o app pela primeira vez com o e-mail cadastrado:

ele deve poder criar a própria conta
o sistema deve validar que o e-mail foi previamente autorizado pelo admin
o cadastro deve ficar vinculado ao usuário criado pelo painel administrativo
3.1 Dados básicos da conta

No primeiro acesso, além do login, o sistema deve orientar a pessoa por um fluxo em etapas.

4. Fluxo de primeiro acesso obrigatório

Quero um fluxo de onboarding de primeiro acesso em etapas, com visual profissional, bom no mobile e com barra de progresso.

4.1 Etapas obrigatórias

Quero que o primeiro acesso inclua pelo menos estas etapas:

Etapa 1: Foto de perfil

preview da foto
opção de trocar antes de salvar

compressão e otimização
Etapa 2: Dados pessoais

Campos obrigatórios:

nome completo
data de nascimento
CPF
telefone
data de admissão

Também quero prever:

cargo
setor
unidade

Mesmo que alguns desses já venham do admin, o sistema deve permitir completar e confirmar.

Etapa 3: Valores da empresa
mostrar uma tela com os valores da empresa
o usuário deve confirmar que leu
registrar data/hora da confirmação
Etapa 4: Termos e documentos
mostrar os documentos obrigatórios de primeiro acesso

permitir apenas confirmação de leitura, quando não exigir assinatura
Etapa 5: Uso de imagem

Quero que os termos de uso de imagem já existentes sejam apresentados como escolha explícita:

aceitar e assinar
ou não aceitar

Etapa 6: Finalização
mostrar resumo do que foi concluído
indicar pendências, se houver
liberar acesso ao app após conclusão mínima obrigatória
5. Máscaras e formatação automática dos campos

Quero tratamento automático de formatação para os campos abaixo.

5.1 Data de nascimento

Campo com preenchimento automático no formato:

DD/MM/AAAA

À medida que a pessoa digita os números, a máscara deve aplicar automaticamente.

Exemplo:

digitou 01011990 → mostrar 01/01/1990
5.2 Data de admissão

Quero o mesmo comportamento:

DD/MM/AAAA
com máscara automática
validação real de data
5.3 CPF

Campo com máscara automática:

000.000.000-00

Também deve:

aceitar apenas números
aplicar pontuação automaticamente
validar tamanho
impedir CPF inválido se houver validação disponível
5.4 Telefone

Quero campo com máscara automática para telefone brasileiro:

DDD com parênteses
2 dígitos de DDD
9 dígitos de telefone

Formato:

(31) 99999-9999

Regras:

aceitar somente números
preencher automaticamente os parênteses e separador
limitar ao total correto
validar quantidade de dígitos

8. Popup de confirmação com texto editável por documento

Quero expandir o sistema de assinatura.

Quando um documento exigir assinatura, o popup de confirmação da assinatura deve poder ter um texto personalizado e editável para cada documento, configurado no admin.

8.1 Exemplo

Ao invés de sempre mostrar o mesmo texto, quero que cada documento possa ter seu próprio texto de confirmação.

Exemplo:

“Confirmo que estou ciente das regras de segurança descritas acima.”
“Autorizo o uso da minha imagem nos termos deste documento.”
“Confirmo ciência e concordância com os valores e diretrizes institucionais.”
8.2 No painel admin

Ao criar ou editar documento, incluir um campo:

Texto do popup de assinatura
ou
Mensagem de confirmação da assinatura

Esse texto deve:

ser opcional
ser editável
aparecer no momento da assinatura
funcionar tanto para texto nativo quanto para PDF
ser salvo junto do documento

Se estiver vazio, usar texto padrão do sistema.
